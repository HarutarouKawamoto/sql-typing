## なぜ

- **丸めずに許容誤差で比べる**：最初は値を丸めて `Map` で数えていた。実装検証で、丸めの目盛りの境目をまたぐと差が 2e-10 でも別の値になると指摘された。12桁・10桁に丸める案も試したが、どの桁でも境目は残る。数値以外の列で組に分け、組の中で1行ずつ許容誤差で探す形にした
- **NaN・Infinity を文字の印にする**：`JSON.stringify` で null になり、`SELECT 'NaN'::float8` が `NULL` の正解と同じになっていた（実装検証の指摘。間違いが正解になる向き）
- **`ignoreColumns` を足した**：`INSERT` で `VALUES` の行の順番を変えただけの正しい書き方が、SERIAL の id の付き方で落ちる。SERIAL の列を自動で見分けるより、問題ごとに書く方が問題を書く人に見える
- **DROP TABLE を `tableMissing` にした**：比べるテーブルを読むと 42P01「そのテーブルはありません」になり、学習者には自分が消したと伝わらない
- **`checkWrongChoices` は判定そのものを使う**：「間違いの選択肢を入れても正解にならない」を、判定と別の比べ方で確かめると、判定とずれる。ruleViolation（結果は同じで条件だけ違う）も、モード2では間違いが区別できないので指摘する
- **`checkOrderDetermined` を行全体で並べるサブクエリにした**：ctid を足す形は GROUP BY・JOIN で必ずエラーになり、中級の問題を足した瞬間に正しい問題が検証で落ちる（実装検証の指摘）
- **`require`・`forbid` を記号を残したトークンで探す**：記号を飛ばすと `ORDER, BY` が ORDER BY になり、`t.in` が IN になり、`SELECT 30 AS count` で COUNT を使ったことになった
- **エラーの原因を原文の形で出し分ける**：同じ 42P01 でも「別名のテーブルを元の名前で書いた」は「つづり間違い」と原因が違う。初級に日付の列があるので、日付のエラー 22007・22008 も足した
