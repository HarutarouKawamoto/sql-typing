## なぜ

- **DB の仕事の列を足した**：SqlRunner は1回の呼び出しごとには順に動くが、判定は reset → 実行 → reset の3回呼ぶ。実装検証で、判定の途中で Esc で離れてすぐ開き直すと、残った判定の reset が次の問題の正解づくり（書き換え系なら reset → 正解SQL → テーブルを読む）の途中に入り、正解の結果が元のままになる経路を指摘された。判定を途中で止める手段がないので、仕事ごと列に並べた
- **時計を、正解だった実行を押したときで止める**：判定のたびに DB を作り直すので、判定には時間がかかる。実行の回数が多いほど、学習者の書く速さと関係のない時間が入るため
- **クリアの結果で見出しにフォーカスを移す**：入力欄にフォーカスがあると、入力欄の Enter は改行なので「もう一度」にできない。見出しに移すと、Enter でもう一度・Esc でもどるがモード1と同じになる
- **テーブルの一覧を仮で出す**：モード4は依頼の文だけで書くので、テーブル名や列名を知る手段がないと書けない。DBの地図（SchemaMap）ができたら置き換える
- **依頼の会話を全部の行で並べる**：会話を1行ずつ送る StoryPanel は一覧・会話の作業で作る。それまでは書く画面の上に並べる
- **ステップ再生が入力欄のキーを奪わないようにした**：書く画面で、間違えたSQLのステップ再生を見ながら入力欄で ← → を押すと、カーソルが動かずにステップ再生が動いていた
- **最高記録はヒントの少ない回を先に・書きかけがあるときだけ Esc を確かめる**：本人の決定（2026-11-12）。実装検証の提案9・7を「判断してほしいこと」に書き、本人が選んだ
- **Esc の確かめは画面の中の1行にした**：`window.confirm` はキーボードの流れを止め、E2E でもダイアログの扱いが要る。もう一度 Esc でもどる形なら、なぞり書きと同じ Esc の感覚のまま、誤って押したときだけ止まる
- **`PlayMode34.jsx` という名前**：リポジトリ構造の「`PlayMode1.jsx` 〜 `PlayMode34.jsx` に分ける」に合わせた（最初は `PlayModeWrite.jsx` で作った）
