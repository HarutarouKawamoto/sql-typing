# 要求内容

## 概要

見える化A（ステップ再生）を作る。SQLを実行順（FROM → WHERE → SELECT → DISTINCT → ORDER BY → LIMIT）に1句ずつ光らせ、その時点の表で、行が消える・列が消える・行がまとまる・並び替わる様子を再生する。モード1の結果から見られるようにする。

## 背景

- 決定1・10：見える化の軸は「DB内部の動き」。ステップ再生（A）はその中心
- モード1で ClauseSplitter（句の範囲と実行順）と ResultTable（結果の表）ができたので、その上に作る

## 実装対象の機能

### 1. Stepper（`src/core/stepper/`、テストを先に書く）
- `buildSteps(sql, runner)`：段階ごとの表と、前の段階からの変化（消えた行・消えた列・名前の変わった列・まとまった行・並び替え）を返す
- 初級の単一テーブルの形（FROM・WHERE・SELECT・AS・DISTINCT・ORDER BY・LIMIT）に対応。それ以外（JOIN・GROUP BY・集計など）は `unsupported`
- 最後の段階の表が、元のSQLをそのまま実行した結果と一致しなければ `ok: false`（間違った見える化を見せない）

### 2. StepPlayer（画面）
- SQLの各句に実行順の番号を付け、今の句を光らせる
- 再生・一時停止・1ステップ進む・戻る・最初から。キーボードでも操作できる（→ ← Space）
- 行が消える段階は、消える行を赤くしてから消す。行数の変化（「30行 → 12行」）を出す
- 再生の速さは学習記録の設定（`replaySpeed`）に合わせる

### 3. 入口
- モード1のクリアの結果に「ステップ再生を見る」を出す。押すと、打ったSQLのステップ再生に切り替わる

### 4. 学習記録
- 最後の段階まで見たら `stepReplayFinished` を記録する（KPI「見える化の利用」）

## 受け入れ条件

- [ ] 初級9問の正解SQLの形すべてで、最後の段階が元のSQLの結果と一致する（統合テスト）
- [ ] WHERE で消えた行、SELECT で消えた列と AS の名前、DISTINCT でまとまった行、ORDER BY の並び替え、LIMIT で消えた行が正しい
- [ ] JOIN・GROUP BY・集計関数・サブクエリの FROM などは `unsupported` になり、画面は「この形のステップ再生はまだありません」と最終結果だけ出す
- [ ] 1問目をクリアして「ステップ再生を見る」を押すと、FROM（30行）→ SELECT の段階を進める・戻れる（E2E）
- [ ] 最後の段階まで見ると `stepReplayFinished` が保存される
- [ ] `src/core/` の行カバレッジ 90% 以上

## スコープ外

- 見える化B（書いた順→実行順の並び替え）・D（予想クイズ）
- 中級の GROUP BY・JOIN の段階（P1。`stepper/` に句の関数を足す形にしておく）
- モード3・4からの入口（判定の作業で足す）
- 初級2〜9問目の問題データ
