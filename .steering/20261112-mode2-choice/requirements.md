# 要求内容

## 概要

モード2（打って選ぶ）を遊べるようにする。表示用SQLのうち空欄以外はなぞり書きで打ち、空欄に来たら選択肢（正解＋間違い、2〜4個）が出る。選択肢を打っていくと合う候補が光り、1つを最後まで打ち切ると選んだことになる。間違いを選ぶと「なぜ違うか（why）」が出て、その空欄を最初からやり直す。句を打ち終えるたびに結果の表が変わり（見える化C）、最後まで打つとクリアとして速さ・正確さ・ランクを記録する。

## 背景

- 壁打ちの作る順番は「… → 判定 → モード2〜4 → ストーリー」。モード3・4はできたので、残りはモード2
- 問題データの空欄・選択肢（`blanks`）と、その検証（先頭部分にならない・間違いを入れると結果が変わる）はすでにある。画面だけがない
- 機能設計書に ChoiceEngine の決まり（候補の絞り込み、打ち切りで確定、候補が0なら miss、毎回シャッフル）がある

## 実装対象の機能

### 1. ChoiceEngine（`src/core/choice-engine.js`）
- `startBlank(blank, randomFn)`：選択肢を並べる（並び順は乱数で混ぜる）
- `pressKey(state, key)`：比べ方は TypingEngine と同じ。候補の絞り込み、候補が0なら `miss`、打ち切りで `decidedCorrect` / `decidedWrong`（`why` つき。その空欄を最初から。選んだ間違いは候補から外す）

### 2. 空欄つきのなぞり書き（`src/core/blank-typing.js`）
- 表示用SQLのスロットの中で、空欄の範囲を見つける
- 空欄の外は TypingEngine、空欄の中は ChoiceEngine。正解を選ぶと空欄が埋まり、その後ろを続ける
- 空欄の中で句が終わっていたら、そのことを知らせる（見える化C）。打った・ミスの数は空欄の中も数える
- 空欄がなければ、TypingEngine と同じ動き（モード1もこれで動かす）

### 3. 画面
- モード2の画面：埋まっていない空欄は「？」の箱で隠し、今の空欄の下に選択肢を並べる（候補が光る、打った分の色、選んだ間違いは打ち消し線）
- 間違いを選んだら why を出す
- 結果：速さ・正確さ・ランク・時間・ミス、選び間違えた回数、苦手。ステップ再生も見られる
- 仮の入口に「1問目を打って選ぶ」

## 受け入れ条件

- [ ] 空欄の外はモード1と同じ決まりで打てる（大文字・小文字、Space と Enter、止まる）
- [ ] 空欄に来ると選択肢が並び、打った文字に合う候補だけが光る。どれにも合わないキーは miss で進まない
- [ ] 間違いの選択肢を打ち切ると why が出て、その空欄を最初からやり直す。選んだ間違いはもう候補にならない
- [ ] 正解を打ち切ると空欄が埋まり、その後ろを続けて打てる。句が終わっていれば結果の表が変わる
- [ ] 最後まで打つとクリア。速さ・正確さ・ランクが学習記録のモード2に残る
- [ ] 選択肢の並び順は乱数で決まる（コアは乱数を引数で受け取る）
- [ ] モード1の動きは変わらない
- [ ] 表示用SQLの中で空欄の範囲が見つからない問題は、問題データの検証で止まる
- [ ] `npm run check` と `npm run test:e2e` が通る。`src/core/` の行カバレッジ 90% 以上

## 成功指標

- 本人が1問目をモード2で遊んでクリアできる
- 初級2〜9問目を足したとき、データを書くだけでモード2が遊べる
