# 要求内容

## 概要

モード1（なぞり書き）を遊べるようにする。表示された正解SQLを打ち写し、打ち間違えたら止まり、句を打ち終えるたびに結果の表が変わる（見える化C）。打ち終えたら速さ・正確さ・ランク・苦手を出し、学習記録に保存する。

## 背景

- 開発ガイドラインの順番は「DBが動く → モード1 → 見える化A → 判定 → モード2〜4 → ストーリー → 上級の見える化」。DBが動いたので、次はモード1
- タイピングの判定（TypingEngine）と句の分解（ClauseSplitter）は、モード2・ステップ再生・判定でも使う土台になる

## 実装対象の機能

### 1. コアレイヤー（`src/core/`、テストを先に書く）
- `sql-text.js`：SQLの字句解析（単語・文字列・数・記号・空白・コメント）
- `clause-splitter.js`：SQLを最上位の句に分け、範囲・書いた順・実行順を返す
- `typing-engine.js`：打つべき文字の列（スロット）を作り、1キーごとに正誤を判定し、句の終わりを知らせる
- `scoring.js`：速さ（cpm）・正確さ・ランク・苦手の集計

### 2. データレイヤー（`src/data/`）
- `problem-loader.js`：章・問題・用語・登場人物の YAML を読み、Zod で確かめる
- `progress-store.js`：学習記録の読み書き（壊れていたら初期化）、遊んだ結果の記録

### 3. 問題データ
- 初級の1問目（`beginner-01`：`SELECT * FROM products`）と、用語辞典の `SELECT`・`FROM`

### 4. 画面
- 仮の入口：データベースの準備ができたら「1問目をなぞり書きで遊ぶ」を押せる（一覧画面・会話は後の作業）
- 遊ぶ画面（モード1）：薄い正解SQLの上に打った文字が重なる、ミスは赤く光って止まる、横に結果の表（句を打ち終えるたびに変わる）、上に経過時間・速さ・正確さ
- 結果：速さ・正確さ・時間・ランク・苦手の上位3つ。学習記録に保存。Esc で入口に戻る

## 受け入れ条件

### タイピング
- [ ] キーワードは小文字で打っても正解。文字列 `'...'` の中は大文字・小文字を区別する
- [ ] 空白・改行は Space 1回。表示上の改行は Space か Enter のどちらでもよい
- [ ] 打ち間違えると位置は進まず、その文字が赤く光る。Shift・Backspace などは無視
- [ ] 句（`FROM products` など）を打ち終えるたびに、そこまでのSQLを実行して結果の表が変わる。実行できない途中（`SELECT *` だけ）では前の表のまま
- [ ] 打っている途中の実行は、前の実行が終わっていなければ最新の1つだけを実行する
- [ ] 最後まで打つとクリアになり、結果が出る

### 記録とスコア
- [ ] 速さ＝正しく打ったスロット数 ÷ 分、正確さ＝正しく ÷（正しく＋ミス）× 100、ランクは機能設計書の表
- [ ] 苦手は、記号はその1文字、英字はそのスロットを含むキーワード（用語辞典にあるもの）で数える。`typed` が20回以上のものから割合の大きい順に3つ
- [ ] クリアと最高記録（速さが速い方）と日ごとの記録が localStorage に残り、読み込み直しても残っている
- [ ] 学習記録が壊れていても起動し、そのことを1回だけ表示する

### 安全柵
- [ ] `src/core/` の行カバレッジ 90% 以上を `npm run check` で確かめる（`@vitest/coverage-v8`）
- [ ] E2E：1問目をモード1で最後まで打ってクリアできる。ミスで止まる。小文字でも通る。途中で表が30行になる

## 成功指標

- 本人が1問目をモード1で遊べる。次の作業（見える化A）が ClauseSplitter をそのまま使える

## スコープ外

以下はこのフェーズでは実装しません:

- 一覧画面・モード選択・依頼の会話（ストーリー）・次の問題へ
- 見える化A（ステップ再生）・B（並び替え）・DBの地図・用語の説明（KeywordTip）
- モード2〜4、判定（Judge）
- 初級の2〜9問目
