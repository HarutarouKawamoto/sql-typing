# 要求内容

## 概要

上級の章（11問とターニングポイント）を足す。テーマは「セール当日を乗り切る」。3つ以上の結合・自己結合・WITH・ウィンドウ関数・実行計画・インデックス・テーブル設計（CREATE TABLE と制約）・トランザクション（行の鍵）を、同じお店の DB で学ぶ。ターニングポイントは、セール当日の障害「注文が二重に入って在庫がマイナスになる」を直す。

## 背景

- PRD「上級の章」、壁打ちの決定8（上級の内容とターニングポイント）
- 上級の見える化（インデックスの比較・実行計画の木・トランザクションのタイムライン）は作ってあるが、出す問題がまだない
- 前の作業の申し送り：タイムラインの場面の商品（id 4）が初期データ（在庫 3）と合っていない

## 実装対象の機能

### 1. 判定：`compareQuery`
- 作る系（`CREATE INDEX`・`CREATE TABLE`）は行を書き換えないので、テーブルの中身では正しさを比べられない
- 問題の `judge.compareQuery`（SELECT）を、学習者の SQL のあとに流し、その結果を比べる（カタログから作ったインデックスの列・テーブルの列と制約を読む）。`compareTable` とは一緒に書けない
- データ検証：`compareQuery` の問題は、正解 SQL のあと `compareQuery` が1行以上を返す

### 2. タイムラインの場面を直す・足す
- 場面の商品を、初期データで在庫1個の Shoulder Bag Leather（id 28）にする
- 3つ目の場面「1文で確かめて減らす（`UPDATE ... WHERE id = 28 AND stock > 0`）」：後から来た方は待ち、確定した在庫 0 で条件を確かめ直して1行も変えない（ターニングポイントの直し方）
