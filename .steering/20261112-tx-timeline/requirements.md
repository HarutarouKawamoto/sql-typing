# 要求内容

## 概要

上級の見える化C「トランザクションの2列タイムライン」を作る。セールの限定品（在庫1個）を、お客さん A と B が同時に注文する場面を、左右2列のタイムラインで見せる。学習者が A と B の SQL を、好きな順に1つずつ実行する。順番によっては在庫が -1 になり、1個しかない品に注文が2つ入る。`SELECT ... FOR UPDATE` で行に鍵をかけると、後から来た方が待ち、在庫 0 を見て注文をやめる。

## 背景

- 壁打ちの決定11：上級の見える化 C。PGlite は接続が1つなので、ここだけシミュレーション
- PRD「上級の章」：在庫1個に2人が同時に注文する場面。学習者が左右のSQLを実行する順番を選ぶ
- 上級のターニングポイント「セール当日に注文が二重に入る」の土台
- 本人の「続けて、トランザクションのタイムラインを作って」（2026-11-12）

## 実装対象の機能

### 1. シミュレーション（`src/core/tx-simulation.js`）
- 2つの場面：鍵なし（`SELECT` で在庫を見てから `UPDATE`）と、鍵あり（`SELECT ... FOR UPDATE`）
- A・B それぞれの手順：BEGIN → 在庫を読む →（1以上なら）UPDATE で減らす → INSERT で注文 → COMMIT。0なら ROLLBACK
- PostgreSQL（READ COMMITTED）と同じ見え方：
  - 自分の変更は自分だけに見え、COMMIT までは相手に見えない
  - `UPDATE`・`FOR UPDATE` は行の鍵がいる。相手が鍵を持っていれば待ち、相手の COMMIT・ROLLBACK で進む（進むときは確定した最新の在庫を使う）
- 結果：両方が終わったら、確定した在庫と注文の数。在庫がマイナスなら「売りすぎ」
- 決まった順で進める（`autoRun`）：指定の側が進めないときは、もう片方を進める

### 2. 画面（`TxTimeline`）
- 場面の切り替え（鍵なし・FOR UPDATE）
- 左右の列に A・B。各列の下に「次を実行：<SQL>」のボタン（待っている・終わったときは押せない）
- 実行した SQL を時間の順に1行ずつ、その側の列に積む。行ごとに一言（「在庫 1 が見えた → 注文する」「待っている（A が鍵を持っている）」など）
- 今の状態：DB に確定した在庫・注文の数、鍵を持っている人
- 「両方が先に読む順で進める」（売りすぎが起きる順の見本）と「やり直す」
- 両方が終わったら結果の文（売りすぎ／守れた）
- 読み上げ：最後に実行した一言を `role="status"` で

### 3. つなぐ
- 書く画面（モード3・4）：問題に `visual: { kind: transaction }` があれば、実行したあと（エラー・打ち切りでなければ）タイムラインを出す
- 見本のページ：「上級：トランザクション（在庫1個に2人が注文）」

## 受け入れ条件

- [ ] 鍵なしで両方が先に読むと、在庫 -1・注文2つ（単体テスト）
- [ ] 鍵なしでも A が先に全部終われば、B は在庫 0 を見てやめる（単体テスト）
- [ ] 鍵ありでは、どの順でも在庫は 0 以上で注文は1つ（単体テスト。全部の順を試す）
- [ ] 待っている側は進めず、相手の COMMIT で進む（単体テスト）
- [ ] 見本のページで、ボタンで1つずつ進めて売りすぎが起き、FOR UPDATE では待つ（E2E）
