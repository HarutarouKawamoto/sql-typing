# 要求内容

## 概要

お店のDBのテーブルとつながりを、箱と線の図（DBの地図、`SchemaMap`）で見られるようにする。箱にはテーブル名と列名・型、線は外部キーのつながり。今の問題のSQLが触っているテーブル（とつながりの線）を光らせ、その章で新しく増えたテーブルに印を付ける。テーブルを選ぶと中身（先頭20行）を見られる。

## 背景

- PRD 機能10（P0）。壁打ちの決定11 の上級の見える化の「D DBの地図（全レベル共通）」。作る順は D → A → B → C
- 本人の「上級まで作って」（2026-11-12）の最初の機能。中級でテーブルが増える前に、地図の仕組みをそろえる
- モード3・4の「使えるテーブル」の一覧は「DBの地図ができるまでの仮」と書いてある

## 実装対象の機能

### 1. 触っているテーブル（`src/core/touched-tables.js`）
- `touchedTables(sql, tableNames)`：SQLの中に出てくるテーブル名（文字列・コメントの外の語、大文字・小文字は区別しない。`"products"` のように引用符で囲んだ名前も）を、`tableNames` の順で返す
- 打っている途中のSQL・エラーになるSQLでも使える（字句だけで見る）

### 2. スキーマの読み込み（`src/data/schema-info.js`）
- `loadSchema(runner)`：`public` のテーブルごとに列（名前・短い型・主キーか）と、外部キーのつながり（どの列がどのテーブルのどの列を指すか）を返す
- `loadTablePreview(runner, table, limit = 20)`：先頭の行（結果の表の形）と全部の行数。テーブル名は引用符で囲んで安全に組み立てる

### 3. 地図（`SchemaMap`・`SchemaMapPanel`）
- 章の `tables` にあるテーブルだけを箱にする（学習者が作ったテーブルは出さない）
- 箱：テーブル名、列名と型、主キー（PK）・外部キー（FK）の印。新しく増えたテーブルに「NEW」の印。触っているテーブルは青で光る
- 線：外部キーのつながり。両方のテーブルを触っていたら光る
- 箱の下に「中身を見る」のボタン（テーブルごと）。押すと先頭20行と全部の行数を出す（箱をクリックしても同じ）
- 図は React Flow（`@xyflow/react`）。ページのスクロールを奪わない（ホイールで拡大しない）。キーで箱を消したり選んだりしない

### 4. 出す場所
- **モード選択**：「DBの地図を見る」（開くと地図）。幅の狭い画面でも見られる（PRD 機能13）。触っているテーブルは光らせない（モード4の答えのヒントにならないように）
- **モード1・2**：「DBの地図を見る」（依頼の会話の隣、ふだんは閉じる）。表示用SQLが触るテーブルを光らせる
- **モード3・4**：依頼の下に「DBの地図を見る」（ふだんは閉じる）。書いているSQLが触るテーブルを、書くたびに光らせる。テーブルの一覧（今の仮）は、地図を開かなくても名前がわかるように残す

## 受け入れ条件

- [ ] モード選択から地図を開くと、products の箱に7つの列と型が出る。押すと先頭20行と「全30行」が出る（E2E）
- [ ] 幅375pxの画面でも、モード選択から地図を見られる（E2E）
- [ ] モード1で地図を開くと products が光っている。モード4では、書く前は光らず、`FROM products` を書くと光る（E2E）
- [ ] 外部キーのつながりと主キーを読める（統合テスト）。触っているテーブルの見つけ方（単体テスト）

## スコープ外

- 中級のテーブル（customers・orders・order_items）を初期データに足すこと（中級の作業）。線の見た目は、中級のテーブルが入ったときに目で確かめる
- 結合の線を「JOIN の ON で使ったつながりだけ」光らせること（今は両方のテーブルを触っていれば光らせる）
- 一覧画面からの地図（章ごと）
