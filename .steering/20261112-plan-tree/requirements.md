# 要求内容

## 概要

上級の見える化B「実行計画の木」を作る。SQL を `EXPLAIN (ANALYZE, FORMAT JSON)` し、計画の節（テーブルを読む・つなぐ・まとめる・並べる…）を木の図にする。下（テーブルを読む節）から上（結果）へデータが流れ、流れる行が多いほど線が太い。

## 背景

- 壁打ちの決定11：上級の見える化は D → A（インデックス比較）→ B（実行計画の木）→ C。D・A はできている
- PRD「上級の章」：実行計画の木の図（下から上へデータが流れ、行数が多いほど線が太い）
- 本人の「上級まで作って」（2026-11-12）

## 実装対象の機能

### 1. 木の置き方（`src/ui/state/plan-layout.js`）
- `layoutPlan(plan)`：節ごとの位置（葉が下、根が上。子は左から順、親は子の真ん中）と、子 → 親の線（流れる行の数と太さ）
- 太さは行の数の対数で決める（1行と5万行が両方見えるように）

### 2. 実行計画を取る（`src/core/explain.js`）
- `explainQuery({ runner, query })`：初期状態で SELECT を EXPLAIN ANALYZE して、計画と読んだ行・時間を返す（前と後に初期状態へ）。SELECT 以外は断る

### 3. 画面（`PlanTree`・`PlanTreePanel`）
- 節の箱：節の種類（`Hash Join` など）と一言（「つなぐ（片方を表にして探す）」など）、テーブル・インデックス、返した行・回数。実行されなかった節（loops 0）は薄く
- 線：子から親へ。太さは流れる行の数、横に「N行」
- 読み上げ用に、同じ中身を文の入れ子の一覧で出す
- 書く画面（モード3・4）：問題に `visual: { kind: plan }` があれば、実行したあと、書いた SELECT の実行計画の木（エラー・SELECT 以外は出さない）
- 見本のページ：「上級：実行計画の木」の見本（JOIN と集計）
