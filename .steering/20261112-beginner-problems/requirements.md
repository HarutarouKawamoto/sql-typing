# 要求内容

## 概要

初級1章の問題を、1問目だけの今から9問（8問＋ターニングポイント）にそろえる。機能設計書の「初級1章の問題（案）」の表に沿って、2〜8問目とターニングポイントの問題YAMLを書き、`chapters.yaml` と `keywords.yaml` を更新する。問題がそろったので、今まで確かめられなかった「次の問題へ」とターニングポイントの流れを E2E で確かめる。

## 背景

- PRD 機能14（初級1章の問題）と MVP の範囲は「初級1章（8問＋ターニングポイント1問）」
- 4つのモード・一覧・会話・判定・見える化Aの仕組みはそろった。問題データだけが1問
- 前の作業（ストーリーと一覧）で「次の問題へ（Enter・J）」「ターニングポイント」の E2E を、問題を足す作業で必ず足すと残した

## 実装対象の機能

### 1. 問題YAML（`data/problems/beginner/02〜09`）
- 表の正解SQLの形、判定のルール（`ordered`・`checkColumnNames`・`require`）
- 依頼の会話（3〜8行、ターニングポイントは10行程度。1行40文字以内）と反応の会話（1〜4行）。俺つええの味付けと、現実のどの操作の裏で動くかが伝わる一言
- モード2の空欄と、似ているが意味が違う間違いの選択肢（結果が変わるもの）と why
- ヒント3段階（使う句・句の順番・骨組み）
- 長いSQLは `display` で句ごとに改行する

### 2. `chapters.yaml`・`keywords.yaml`
- 初級の `problemIds` を9問に
- 問題で初めて使うキーワード（AS・WHERE・AND・OR・IN・BETWEEN・LIKE・IS NULL・IS NOT NULL・ORDER BY・DESC・ASC・LIMIT・DISTINCT）を用語辞典に

### 3. 問題データの検証
- すべての問題の正解SQLで、ステップ再生が作れる（`mismatch`・`error` にならない）ことを確かめる検証を足す

### 4. E2E
- 1問目をクリアすると2問目が開き、Enter・J で2問目のモード選択へ進む
- ターニングポイントの印と、モード選択の説明。ターニングポイントをモード1でクリアしたあとの画面（次の章はまだないので「次の問題はまだありません」）
- 今の E2E の「1問しかない」前提を直す

## 受け入れ条件

- [ ] 初級が9問になり、一覧に並ぶ。最後の問題にターニングポイントの印
- [ ] すべての問題が問題データの検証を通る（形・会話の行数と長さ・空欄と選択肢・間違いの選択肢で結果が変わる・並びが1つに決まる・句の途中まで実行できる・打てる・ステップ再生が作れる）
- [ ] 1問目をクリアすると2問目が開き、Enter・J で2問目へ進める（E2E）
- [ ] `npm run check` と `npm run test:e2e` が通る

## 成功指標

- 本人が初級1章を順に遊べる
- PRD の KPI「初級1章の修了」を測れる状態になる

## スコープ外

- 中級の章と、ターニングポイントのあとに次の章が開くことの画面での確かめ（次の章がまだない。進む条件は単体テストで確かめている）
- 用語辞典の画面
