## フェーズ4：検証と記録
- [x] 実装検証（implementation-validator）と指摘への対応（[必須] 2件・[推奨] 7件・[提案] 4件。検証役がプレビューで実測し、必須1を見つけた）
  - 必須1 マウスを置いたまま間違えると、文字の要素が作り直され、ブラウザの「当てた」で説明がもどる → マウスが動いていない（最後に動いた位置と同じ）「当てた」は数えない。直したら、画面を開いた直後に止まったカーソルの下に語が来て出る場合も同じ原因とわかり、まとめて直った。E2E を足した
  - 必須2 モード2で、見えている語の説明の「例」から空欄の答えがわかる（6問目の LIKE の例が `'%Mug%'`）→ 埋まっていない空欄があるあいだは、打つSQLのどのスロットにも data-keyword を付けない。E2E を足した
  - 推奨3 同じ語の中を動くと説明が1文字ずつ動く・マウスのクリックで消える → 同じ語（`data-keyword-group`）なら出し直さない。マウスのクリックでは変えない（指で押したときだけ）
  - 推奨4 出した場所が消えても説明が残りうる → 出している間だけ 0.3秒ごとに見て消す
  - 推奨5 用語辞典で問題の読み込みの失敗が出ない → 出す
  - 推奨6 キーボードで見られない・tooltip が誰とも結び付いていない・dt が短い → KeywordText の語に Tab で移れるようにし、`:focus-visible` で出す（タップで付いたフォーカスでは出さない。出すと続く「押した」で消える）。語に `aria-describedby`。「SQLでの意味」「初めて出てくる問題」に
  - 推奨7 keydown の受け方・resize・狭い画面で左が切れる → `onKeyDown` に包む、`resize` で消す、幅の上限を画面の幅 − 16px に
  - 推奨8 用語を import の時点で読む → 最初に使うときに読む（`getKeywordWords`・`getKeywordMap`）
  - 推奨9 スロット → 語の対応のテストがない → core の `keywordsOfSlots` に出し、単体テスト2件を先に書いた
  - 見送り：WCAG 1.4.13 の「説明の上にマウスを移せる」（説明が打つSQL・ボタンに重なっても押せるよう `pointer-events: none` のまま。機能設計書に書いた）、提案（用語辞典から開いた問題のもどり先、Set を毎回作る、keywords の書き忘れの検証、ほかのボタンとの副作用の E2E）は、今の動きで困らないので見送り
