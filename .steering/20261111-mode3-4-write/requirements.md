# 要求内容

## 概要

モード3（ヒントありで書く）とモード4（ヒントなしで書く）を遊べるようにする。依頼を読み、白紙の入力欄にSQLを書いて Ctrl+Enter で実行すると、判定（Judge）の結果が出る。不正解なら理由を見て書き直し、正解ならクリアとして時間・実行した回数・開いたヒントの数を記録する。実行のたびに、書いたSQLの結果の表とステップ再生（見える化A）を見られる。

## 背景

- 判定の作業のスコープ外に「モード2〜4の画面（次の作業）」と残した。判定はできたが、画面からはまだ使われていない
- PRD の機能6（モード3・4）と機能7（判定）の受け入れ条件は、画面がないと満たせない
- ステップ再生の作業で「モード3・4からの入口は判定の作業で足す」と残したが、判定の作業では画面を作らなかったので、ここで足す
- ターニングポイントはモード3・4でしかクリアできないので、章を進めるためにも要る

## 実装対象の機能

### 1. 書く画面（モード3・4）
- 依頼の会話（`story.before`）を、話している人の名前つきで読める（会話を1行ずつ送る StoryPanel は、一覧・会話の作業で作る）
- 使えるテーブルと列の一覧（DBの地図ができるまでの仮。書く前に、どの名前を使えばよいかわかるように）
- SQLの入力欄（複数行）。Ctrl+Enter で実行、Tab でスペース2つ
- 上の帯に、経過時間・実行した回数・（モード3）開いたヒントの数

### 2. ヒント（モード3だけ）
- 3段階のヒントを1つずつ開ける。開いた数を数える
- モード4ではヒントを出さない

### 3. 判定の結果（JudgePanel）
- 正解・不正解（理由の説明）・条件違反・和訳したエラー（よくある原因、英語の原文は折りたたみ）・打ち切り
- 正解ならクリア：かかった時間・実行した回数・開いたヒントの数を出し、学習記録に残す

### 4. 実行のたびの表とステップ再生
- 書いたSQLの結果の表（エラーのときは前の表を消す）
- 「ステップ再生を見る」で、書いたSQLのステップ再生に切り替わる（間違っていても見られる）

### 5. 入口
- 仮の入口に「1問目をヒントありで書く」「1問目をヒントなしで書く」を足す（一覧画面は後の作業）

## 受け入れ条件

- [ ] 入力欄に複数行で書け、Ctrl+Enter で実行すると判定の結果が出る。Tab でスペース2つが入る
- [ ] 不正解のときは理由（行の数・列・値・順番など）が出て、そのまま書き直してもう一度実行できる
- [ ] エラーのときは、和訳した題名とよくある原因が出て、英語の原文を開いて見られる
- [ ] 判定のたびにDBは初期状態に戻る（`DROP TABLE products` のあとでも、正しいSQLで正解になる）
- [ ] モード3ではヒントを1つずつ3つまで開け、開いた数が記録される。モード4ではヒントが出ない
- [ ] 正解でクリアになり、時間・実行した回数・開いたヒントの数が出て、学習記録のモード3・4に残る
- [ ] 実行のたびに結果の表が出て、ステップ再生に切り替えられる。最後まで見たら `stepReplayFinished` が残る
- [ ] 判定している間は、続けて実行しても2つ目を走らせない
- [ ] `npm run check` と `npm run test:e2e` が通る

## 成功指標

- 本人が1問目をモード3・4で遊んでクリアできる
- 次の作業（モード2・初級2〜9問目）で、JudgePanel と書く画面をそのまま使える

## スコープ外

- 見える化B（実行順の並び替え、ReorderIntro）
- モード2（打って選ぶ）
- 会話を1行ずつ送る StoryPanel・クリア後の会話・一覧画面・DBの地図（SchemaMap）
- 幅768px未満の知らせ（一覧画面の作業で入口と一緒に作る）
