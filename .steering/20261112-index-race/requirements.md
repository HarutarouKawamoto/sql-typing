# 要求内容

## 概要

上級の見える化A「インデックスあり・なしの左右比較」を作る。同じ問い合わせを、インデックスがないとき・あるときで `EXPLAIN ANALYZE` し、読んだ行の数（カウンター）・実行にかかった時間・読み方（全部の行を読む／索引で探す）を左右に並べる。あわせて上級の初期データ（アクセスログ5万行）を作る。

## 背景

- 壁打ちの決定11：上級の見える化は D（DBの地図）→ A（インデックス比較）→ B（実行計画の木）→ C（トランザクション）の順。D はできている
- PRD「上級の章」：インデックスあり・なしの左右比較（読んだ行数のカウンター、5万行ほどのデータで EXPLAIN ANALYZE の実測時間を並べる）
- 本人の「上級まで作って」（2026-11-12）

## 実装対象の機能

### 1. 上級の初期データ（`data/seeds/advanced.sql`）
- 中級の `intermediate.sql` をそのまま含め、アクセスログ `access_logs`（id・customer_id・session_id・path・accessed_at）5万行を `generate_series` で足す。session_id はすべて違う

### 2. 実行計画を読む（`src/core/explain.js`）
- `parseExplain(raw)`：`EXPLAIN (ANALYZE, FORMAT JSON)` の結果を、計画の木（節ごとの種類・テーブル・インデックス・行数・取り除いた行・時間・子）と、実行・計画にかかった時間にする
- `rowsRead(plan)`：テーブルから読んだ行の数（Seq Scan は返した行と条件で取り除いた行の合計。索引で探す節も同じ考え方）
- `compareChange({ runner, query, changeSql })`：初期状態で `query` を EXPLAIN ANALYZE → `changeSql`（インデックスを作るSQLなど）を実行 → もう一度 EXPLAIN ANALYZE → 初期状態に戻す。2つの結果を返す

### 3. 画面（`IndexRace`）
- 左「インデックスなし」・右「インデックスあり」。読んだ行の数がカウンターで増えていき（1.2秒）、横の棒の長さも比べられる。かかった時間、読み方（全部の行を読む Seq Scan／索引で探す Index Scan など）の一言
- 書く画面（モード3・4）：問題に `visual: { kind: index, query }` があれば、実行したあと、学習者のSQLを「変える前と後」の間に入れて比べる（例：学習者が CREATE INDEX を書く）
- 見本のページ（`/?demo`）：「上級：インデックス」の見本（session_id で1行を探す問い合わせ、インデックスを作るSQL）。見本のページは上級の初期データで開く

## 受け入れ条件

- [ ] 上級の初期データの決まり（統合テスト）
- [ ] 実行計画の読み方・読んだ行の数（単体テスト。PGlite の実際の出力の形で）
- [ ] インデックスなしは5万行を読み、ありは1行（統合テスト）
- [ ] 見本のページで、左右の読んだ行の数と読み方が出る（E2E）
